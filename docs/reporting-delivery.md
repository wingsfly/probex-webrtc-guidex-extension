# 上报去重与升级说明

## 问题与修复

2026-09-10 排查发现，同一页面的交互与 WebRTC 样本被插件代理和页面直接请求各发送一次。插件更新后，旧监听返回“扩展上下文失效”，抢先触发页面回退，而新监听的代理请求仍继续执行。

1. `content-script.js` 在同一隔离环境内只注册一次监听。失效实例退出并移除监听，不参与有效实例的握手。
2. 页面与转发脚本使用 v2 消息和独立实例标识，旧 v1 响应不能完成新请求；多个有效实例也只选中一个。相同请求消息重复到达时，共享一次转发。
3. 先通过无 HTTP 副作用的握手选定通道。仅握手未发现有效代理时，允许页面直接请求；已交给代理的 POST 不因失败或超时再次走页面通道。
4. 每条 WebRTC、Legacy 和 Runtime 样本在进入待上报队列时生成 `result_id`。重试保留 ID、时间戳和内容，不重新生成一条样本。每类探针最多一批请求在途。
5. ProbeX 后端使用“探针名、任务、agent、页面、result_id”确定唯一入库 ID，依赖现有主键事务去重。首次成功写入生效，重复请求不覆盖记录、不重复评估告警。

`result_id` 位于 `results[]` 的传输封装中，不在 `extra` 业务指标内，不改变 GuideX 时间线字段，也不触发历史清理。

## 边界

- 后端返回 `accepted`（新增与重复合计）、`inserted`、`duplicates`，成功重放仍返回 200。
- 不携带 `result_id` 的旧客户端保持原有追加语义；旧后端会忽略该字段，因此无法防止“已入库但响应丢失”后的重试重复。应先升级后端。
- 相同 ID 的首次入库内容不可覆盖。不同样本必须使用不同 ID，不能仅按时间戳、文本或指标值合并。
- 去重依赖原始记录保留，跨后端重启有效；既有保留策略或明确清理删除原始记录后，对应去重键不再存在。本次修复不删除既有重复数据。
- 队列仅保存在页面内存且有容量上限，不保证长期离线无损。页面刷新、队列满、切换 Hub/agent/Probe Name 可能丢弃待上报数据；切换身份时不会把旧队列作为新身份重发。已经发出的请求仍可能到达原目标。

## 生效步骤

1. 部署包含幂等接口修复的 ProbeX 后端，不需要数据库迁移或清库。远端部署须遵守基础设施 inventory、preflight 和实例运维说明。
2. 在 `chrome://extensions/` 重新加载插件，确认版本为 **1.1.4**（包含此前去重和 `LastAudio_To_*` 修复，移除 `Audio_To_Speech` 并使用 `Answer_Dur/Play_Dur` 短名；需配套新版 ProbeX 前端）。
3. 等当前对话结束后刷新每个需要监测的 GuideX 页面。旧采集器会在新弹窗中显示 `Reload page`，不能将文件更新视为页面已更新。
4. 旧 `report-app` 页面选择 Auto/Legacy，新 Runtime 页面选择 Auto/Runtime v4；点击 Save 保存。
5. 执行一轮真实对话，在相应任务下确认新增一条结果。重试可以产生多个 HTTP 请求，但同一稳定 ID 只能新增一条数据库记录。

代码完成和离线测试通过不代表已部署到 yghk，也不代表已重新加载用户当前的 Chrome 页面。生产验收应单独确认。

## 离线回归

- 插件目录：`npm run check`，覆盖重复注入、旧实例失效、多实例选择、超时/失败不跨通道重发、三类结果稳定重试，以及页面版本提示。
- ProbeX 目录：`go test -race ./...`，覆盖批内重复、跨批重放、并发请求、不同作用域、旧客户端兼容、重启后去重和事务回滚。
- 所有模拟指标仅进入临时测试环境，不向 yghk 写入测试数据。
